实验8 应用层协议模拟（HTTP、DNS、FTP、DHCP）

Created2026-04-28|Updated2026-04-28|计算机网络实验
|Post Views:

一、实验目的

  1. 理解 HTTP 协议的工作原理，掌握在 eNSP 中搭建 Web 服务器并通过客户端访问的方法。
  2. 理解 DNS 协议的域名解析过程，掌握在 eNSP 中配置 DNS 服务器实现域名访问的方法。
  3. 理解 FTP 协议的文件传输机制，掌握在 eNSP 中配置 FTP 服务器并完成上传、下载操作。
  4. 理解 DHCP 协议的自动地址分配原理，掌握在华为路由器上配置 DHCP 服务器的方法。
  5. 能够使用 Wireshark 抓包分析各协议的数据交互过程。

二、实验环境

  1. 硬件：个人电脑（建议内存 8G 以上，以流畅运行 eNSP）。
  2. 软件：
    • eNSP V100R003 或更高版本。
    • Wireshark（用于协议抓包分析）。
    • VirtualBox（eNSP 运行底座）。

三、实验内容及步骤、结果

1. HTTP 服务配置与访问

1.1 拓扑搭建

  • 操作：
    1. 打开 eNSP，新建拓扑。
    2. 拖入一台 Client 终端和一台 Server 服务器，使用连接线直连。
    3. 点击工具栏的"开启"按钮，等待设备图标由红变绿。

1.2 Client 与 Server IP 地址配置

  • Client 配置 IP：
  • Server 配置 IP：

Client 与 Server 处于相同网段，可以不配置网关。

1.3 连通性测试

  • 在 Client 上 ping Server 地址，验证网络连通。

1.4 配置 HTTP Server

  • 在 Server 的 HTTP 服务器设置中启用 HTTP 服务，配置首页文件等信息。

1.5 客户端访问 HTTP Server

  • 在 Client 的浏览器地址栏输入 Server 的 IP 地址，访问 Web 页面。

1.6 多客户端访问（扩展）

  • 在拓扑中增加一台 S5700 交换机，连接多个 Client，实现多客户端同时访问 HTTP Server。

思考：如果中间放路由器而非交换机，需要如何配置才能实现跨网段访问？

2. DNS 服务配置与域名解析

2.1 拓扑搭建

  • 拖入 Client 和 Server，Server 同时承担 DNS Server 和 HTTP Server 的角色。

2.2 配置 DNS Server

  • 在 Server 上启用 DNS 服务，添加域名与 IP 地址的映射记录。

2.3 配置 Client 并验证

  • 在 Client 上设置 DNS 服务器地址为 Server 的 IP。
  • 在 Client 的浏览器中输入域名，验证 DNS 解析是否成功。

3. FTP 服务配置与文件传输

3.1 配置 FTP Server

  • 在 Server1 上启用 FTP Server 功能，设置 FTP 根目录及用户信息。

3.2 Client 端连接 FTP

  • 在 Client1 上通过 FTP 客户端登录 FTP Server。

3.3 验证 FTP 上传与下载

  • 在 Client1 上执行文件上传（put）和下载（get）操作。

3.4 Wireshark 抓包分析 FTP

  • 使用 Wireshark 抓取 FTP 数据包，观察 FTP 的命令交互与文件传输过程。

4. DHCP 服务配置与自动地址分配

4.1 拓扑搭建

  • 拖入一台 AR2220 路由器作为 DHCP Server，通过交换机连接多台 Client。

4.2 路由器 DHCP 配置

R1：

关键配置说明：

  • dhcp enable：全局开启 DHCP 功能。
  • ip pool R1：创建名为 R1 的地址池。
  • network 192.168.1.0 mask 24：设置可分配的 IP 地址范围。
  • gateway-list 192.168.1.1：设置分配给客户端的默认网关。
  • dns-list：设置 DNS 服务器地址。
  • dhcp select global：接口使用全局地址池分配 IP。

4.3 DHCP 抓包分析

  • 步骤：

    1. 将 Client 先设置为 静态 IP 模式。
    1. 在链路上启动 Wireshark 抓包。
    1. 将 Client 切换为 DHCP（动态获取） 模式。
    1. 查看 Wireshark 抓包结果，观察 DHCP 的 Discover → Offer → Request → Acknowledge（DORA）四步交互过程。

四、思考题

  1. HTTP 与 HTTPS：HTTP 和 HTTPS 有什么区别？为什么现代网站普遍使用 HTTPS？
  2. DNS 解析流程：当客户端输入一个域名时，DNS 解析的完整流程是怎样的？递归查询与迭代查询有什么区别？
  3. DHCP 四步交互：DHCP 的 DORA（Discover、Offer、Request、Acknowledge）过程中，为什么 Client 在收到 Offer 后还需要发送 Request？如果网络中存在多台 DHCP 服务器会怎样？
  4. 协议对比：HTTP、FTP 都可以用于文件传输，它们各自适用的场景有什么不同？
